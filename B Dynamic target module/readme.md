# Dynamic Target Module

This directory contains the simulation and analysis codes for the **dynamic target-module stimulation** condition in a modular neuronal network.

The model consists of an eight-module neuronal network with fixed modular connectivity. During the simulation, external stimulation is applied sequentially to the network modules, with the **target module randomly selected for each stimulation window**. The familiarity parameter \(F\) controls the allocation of external input between the currently stimulated module and the remaining modules.

The simulation alternates between stimulation and pause intervals. During a stimulation window, the selected target module receives enhanced external input, while the remaining modules receive a weaker background input. During the subsequent pause interval, external stimulation is removed. The neuronal and synaptic states are updated at each time step according to the model equations.

The outputs of the simulation can then be analyzed to determine how well the externally stimulated module can be identified from the resulting network activity and how long activity persists after stimulation has ended.

---

## Contents

This directory contains six files:

### 1. `Simulation.cpp`

C++ implementation of the network model and simulation.

The program:

* reads a pre-generated modular network from the input files;
* initializes the neuronal and synaptic states;
* randomly selects a target module during each stimulation window;
* applies external input according to the familiarity parameter \(F\);
* evolves the network dynamics in discrete time;
* records the activity of each module over time; and
* records the identity of the externally stimulated module.

The program performs a **single realization** on a fixed network topology. The network connectivity remains unchanged throughout the simulation, while the target module changes randomly between successive stimulation windows.

The simulation produces two output files:

* `ActivityInTime.txt` — time-dependent activity of the eight modules.
* `TargetModuleInTime.txt` — identity of the module receiving external stimulation at each time step. A value of zero denotes the pause interval between stimulation windows.

---

### 2. `Analysis.ipynb`

Python/Jupyter notebook for analyzing the output of `Simulation.cpp`.

The notebook:

1. detects burst-activity intervals from the simulated module activity;
2. constructs binary predicted-activity signals for each module;
3. compares predicted activity with the actual stimulated module;
4. calculates a window-level confusion matrix;
5. calculates the corresponding classification accuracy;
6. measures post-stimulus persistence of activity; and
7. generates figures comparing the stimulation sequence, module activity, and predicted burst activity.

The persistence analysis follows the activity of the stimulated module after the external stimulation ends. A persistence event continues while the predicted activity remains nonzero and terminates when the activity disappears or when the same module is stimulated again. Stimulation of other modules does not terminate an ongoing persistence event.

The notebook therefore provides both **stimulus-response classification measures** and **post-stimulus persistence measures** from the same simulation output.

---

### 3. `BlockNodesNumberOfModularNetwork.txt`

Input file specifying the allocation of nodes to the modules of the modular network.

This file is read by `Simulation.cpp` and is used to identify the module membership of each node.

---

### 4. `ModularAdjList.txt`

Input file containing the adjacency-list representation of the modular network.

This file specifies the network connectivity used by `Simulation.cpp`. The topology is read once at the beginning of the simulation and remains fixed throughout the realization.

---

### 5. `ActivityInTime.txt`

Example output generated by `Simulation.cpp`.

It contains the time-dependent activity of the eight modules and is provided so that `Analysis.ipynb` can be run directly without first executing the C++ simulation.

The first column contains time, followed by the activity of modules \(1,\ldots,8\).

---

### 6. `TargetModuleInTime.txt`

Example output corresponding to the provided `ActivityInTime.txt`.

It contains the identity of the externally stimulated module at each time step. The value is:

* `1`–`8` during stimulation of the corresponding module;
* `0` during the pause intervals.

The file is paired with `ActivityInTime.txt` and is used by `Analysis.ipynb` to compare the actual stimulation sequence with the module activity inferred from the simulation.

## Model and Simulation Procedure

The simulation uses a discrete-time neuronal network with eight modules. At each stimulation cycle, one module is randomly selected as the target.

For a stimulation window of duration \(\tau_g\), the external activation probability is distributed according to the familiarity \(F\). The target module receives the enhanced input, while the other modules receive the remaining background input. After the stimulation window, a pause interval of duration \(\tau_{\mathrm{pause}}\) follows during which no external input is applied.

The simulation therefore has the following structure:

```text
        Stimulation                Pause
   |-------------------|       |---------|
   Target module selected          No input
          randomly
   |<----- τg -------->|<-- τpause -->|

        Stimulation                Pause
   |-------------------|       |---------|
   New target selected
          randomly
```

The target module is allowed to change from one stimulation window to the next. This dynamic target selection is the defining feature of the present condition.

## Running the Simulation

Compile and run `Simulation.cpp` using a C++ compiler.

For example, with `g++`:

```bash
g++ Simulation.cpp -o Simulation
```

Then run:

```bash
Simulation
```

The program expects the two network input files

```text
BlockNodesNumberOfModularNetwork.txt
ModularAdjList.txt
```

to be available in the working directory.

After execution, the simulation generates:

```text
ActivityInTime.txt
TargetModuleInTime.txt
```

These files can then be analyzed using `Analysis.ipynb`.

> **Note:** Running the simulation will overwrite the corresponding output files if the program uses the same filenames.

---

## Running the Analysis

The notebook can be opened with Jupyter Notebook or JupyterLab:

```bash
jupyter notebook Analysis.ipynb
```

or

```bash
jupyter lab Analysis.ipynb
```

The example `ActivityInTime.txt` and `TargetModuleInTime.txt` files included in this directory allow the analysis notebook to be executed without running the C++ simulation first.

The analysis parameters in the notebook should be kept consistent with the parameters used to generate the simulation output, in particular:

* familiarity \(F\);
* stimulation duration \(\tau_g\);
* pause duration \(\tau_{\mathrm{pause}}\);
* external input probability \(\eta\); and
* burst-detection precision.

---

## Analysis Outputs

The notebook produces a visualization containing:

* the total network activity \(\rho\);
* the activity of individual modules;
* the actual sequence of stimulated modules;
* the predicted burst activity of each module; and
* a comparison between actual and predicted module activity.

It also reports:

### Confusion matrix

Classification is performed at the **stimulation-window level**. For each module and stimulation window:

* **TP** — the module is stimulated and predicted as active;
* **FN** — the module is stimulated but not predicted as active;
* **FP** — the module is not stimulated but is predicted as active;
* **TN** — the module is neither stimulated nor predicted as active.

The pause intervals are excluded from the confusion matrix.

### Post-stimulus persistence

The notebook also measures continued predicted activity following the end of stimulation. The main quantities reported are:

* **CP** — cumulative persistence duration;
* **Number of Memory Events** — number of detected persistence events;
* **AML** — average persistence length; and
* **LME** — longest persistence event.

These quantities characterize the temporal persistence of network activity following external stimulation.

---

## Reproducibility

The modular network topology is provided explicitly through

```text
BlockNodesNumberOfModularNetwork.txt
ModularAdjList.txt
```

and is therefore fixed for the supplied simulation setup.

The dynamic component of this condition is the **random selection of the target module across stimulation windows**, rather than changes in the network topology itself.

The example output files included in this directory provide a reference realization for reproducing the analysis and figures without rerunning the simulation.
